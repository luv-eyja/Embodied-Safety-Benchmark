# ESB-2：具身智能安全综合基准 · 设计方案

> 基于本仓库 192 篇论文 / 121 个基准的系统梳理，以及对 10 篇核心基准论文的全文精读。
> 文档状态：**v0.1 提案**，用于讨论，尚未实现。

---

## 0. 一句话

现有 121 个基准把具身安全切成了 121 个互不相通的单点诊断。**ESB-2 的目标是给出一个坐标系 + 一套判分口径，使得「哪个环节、哪类安全、哪个阶段失效」可以在同一次评测里被定位、被归因、被跨本体比较。**

不是再造一个更难的任务集，而是**给已有的任务集装上一层可复用的安全测量层**。

---

## 1. 为什么需要新基准：五个结构性缺陷

### 1.1 覆盖碎片化 —— 只有 1 个基准跨 4 类以上安全属性

对 121 个基准按「具身环节 × 安全属性」做粗略统计（附录 A）：

| 环节 | 语义/指令 | 物理/接触 | 对抗/后门 | 分布偏移 | 失败恢复 | 实时/治理 | 合计 |
|---|---|---|---|---|---|---|---|
| 感知层 | 21 | 20 | 4 | 24 | 15 | 4 | 88 |
| 认知/语义层 | 36 | 22 | 6 | 13 | 9 | 5 | 91 |
| 规划层 | 13 | 12 | 8 | 12 | 12 | 3 | **60** |
| 动作控制层 | 28 | 36 | 10 | 28 | 20 | 11 | 133 |
| **终态/后果层** | **0** | 6 | **0** | **0** | 1 | 1 | **8** |

两个直接结论：

- **终态/后果层几乎空白**：121 个基准里只有 8 个触及「任务做完之后是否安全」。而机器人伤害人往往发生在终态——刀留在台边、热锅把手朝向人、污染物残留在共用表面。
- **实时/治理只有 24 个**，其中真正把「决策延迟」当一等变量的只有 RT-Safe 一个（城市导航场景）。
- 同时覆盖 ≥4 类安全属性的基准**只有 EmbodiedGovBench 一个**。

### 1.2 阶段不可定位 —— 总分掩盖失效位置

SafeStage 是唯一显式把评测切成「执行前 / 执行中 / 执行后」三阶段的基准（97 个风险场景）。其余绝大多数只报一个聚合安全分。

但 SafeStage 的发现恰恰说明这件事必须做：**不同策略在三阶段的失败画像完全不同**。聚合成一个分数，等于把「策略 A 在执行期撞人」和「策略 B 在终态留下隐患」判为同一个失败。

### 1.3 配对设计各自为政 —— 归因结果无法合并

已有至少五种配对思想，每种只服务自己的论文：

| 配对思路 | 代表 | 配对的是什么 |
|---|---|---|
| 安全/不安全孪生场景 | HazardArena（2000+ 资产、51 任务、7 类标准） | 物体、布局、动作要求完全相同，只改语义语境 |
| 单轴 / 复合扰动配对 | LIBERO-CTRL（六轴） | 同一初始状态的单轴条件 vs 匹配的多轴同时条件 |
| 同场景指令对比 | GuardianBench（3024 组） | 场景固定，只改指令的安全/不安全 |
| 硬件 / latent 偏移 | LIBERO-RIG（11 轴 × 5 严重度 = 210 条件） | 任务固定，只改机器人自身配置 |
| 接口切换 | RoboHarm | 模型固定，只改交互接口（文本 → 代码 → 末端位姿） |

它们共享同一个方法论内核（**控制变量 + 逐实例配对**），但维度不同、报告口径不同，**无法拼成一张图**。

### 1.4 判分口径不一 —— 结论不可比

- ManiGuard：**LTL_f 自动机**在物理谓词上运行时检查，明确拒绝学习分类器与 LLM 裁判
- SafeVLA-Bench：**STL 不变式** + 定量鲁棒性语义
- 其余多数：人工规则、阈值判断，或 LLM-as-judge

同一句「安全率 78%」，在三种口径下不是同一个量。这是当前最容易被忽视、也最影响横向比较的问题。

### 1.5 能力与安全未解耦 —— 单一分数掩盖了二者不同步

DESPITE（12,279 个具身规划任务，确定性验证）给出了最有力的证据：

- 规划能力最好的模型，只有 **0.4%** 任务给不出有效计划，却有 **28.3%** 给出危险计划
- 18 个开源模型（3B–671B）规划能力从 **0.4% 升到 99.3%**，安全意识却只在 **38–57%** 之间持平
- 二者是**乘法关系**：大模型之所以更安全，主要是因为计划做得更完整，而不是更懂得避危险

ManiGuard 独立给出同一方向的证据：**两个任务成功率几乎相同的策略，安全违规率相差 6 个百分点**。

只要基准继续只报 SR，这类差距就永远不可见。

## 2. 设计目标（每条都可检验）

| 编号 | 目标 | 检验方式 |
|---|---|---|
| G1 | **分层定位**：能把失效归到「感知 / 认知 / 规划 / 动作 / 终态」某一层 | 人工注入已知失效，看是否被正确定位 |
| G2 | **配对归因**：能区分「能力不足」与「安全判断错」 | 同一任务的 safe/unsafe 孪生对上，成功率差应接近 0 而安全率差应大 |
| G3 | **形式化判分**：不用 LLM 裁判 | 判分器可复现、可审计、给定同一轨迹输出确定结果 |
| G4 | **双轴报告**：能力与安全分开报，不合成单一分数 | 输出为二维点而非标量 |
| G5 | **latent/observable 分离**：覆盖「不改变图像」的故障 | 视觉扰动训练过的模型在 latent 轴上仍应有退化 |
| G6 | **跨本体**：≥3 个本体、≥2 种末端执行器 | 同一场景在不同本体上的安全结论可比较 |
| G7 | **真机锚点**：仿真排序与真机排序一致 | Kendall τ ≥ 0.7（目标值，需实测） |
| G8 | **可负担**：单模型全量评测 ≤ 8 GPU·天 | 实测 |

G5 的来历值得一提：LIBERO-RIG 发现**在视觉扰动上训练，无法缓解「不改变相机图像」的故障**（驱动增益、控制频率、标定漂移这类 latent 轴）。这意味着现有以图像扰动为主的鲁棒性基准，系统性地漏掉了一整类失效。

## 3. 架构：三层坐标

ESB-2 的每个评测单元由三元组唯一确定：

```
(L 层, A 属性, S 阶段)  +  配对条件 P
```

### 3.1 L 层（具身环节）

| 层 | 判据 | 典型失效 |
|---|---|---|
| L1 感知 | 观测是否足以支撑判断 | 遮挡导致漏检；视角偏移导致误定位 |
| L2 认知/语义 | 是否正确理解「这个动作在当前语境下该不该做」 | 指令歧义；语义风险未被识别 |
| L3 规划 | 动作序列是否安全且可达 | 长时程计划漏掉前置化解步骤 |
| L4 动作控制 | 执行是否在安全包络内 | 接触力超限；轨迹穿越禁入区 |
| L5 终态/后果 | 结束后世界是否仍安全 | 物体失稳；污染物残留；工具朝向人 |

### 3.2 A 属性（安全性质）

A1 任务能力（基线，非安全）· A2 分布偏移鲁棒性 · A3 语义/指令安全 · A4 物理/接触安全 · A5 对抗/后门安全 · A6 恢复与治理

### 3.3 S 阶段

S1 初始态（操作前必须化解的关系）· S2 执行期 · S3 终态

### 3.4 为什么是这三层而不是更多

因为现有基准的**失效证据**恰好落在这三个切面上：
- 按 L 切，能对上 SafeStage 的三阶段与 ForesightSafety 的三侧（Safe-Core/Lang/Vis）
- 按 A 切，能对上 SafeVLA-Bench 的 8 类约束族与 ManiGuard 的 skill × constraint
- 按 S 切，能对上 LIBERO-CTRL 的阶段诊断与 RoboCasa-Shift 的 stage-aware

再细就会失去可操作性。

## 4. 任务与场景体系

### 4.1 原则：不重造仿真，只加测量层

这是本方案与「再发一个 benchmark」最大的区别。基础任务池直接复用：

| 来源 | 提供什么 | 复用理由 |
|---|---|---|
| LIBERO（130 任务 / 4 套件） | 桌面操作底座 | VLA 领域事实标准，复现性最好 |
| RoboTwin（双臂 / 生成式数字孪生） | 双臂与更多物体 | 已是 Trap-RoboTwin、ForesightSafety 的底座 |
| RoboCasa365 | 厨房长时程 | SafeVLA-Bench 已验证可在其上挂约束 |
| BEHAVIOR-1K | 家务活动（ManiUnit 用了 50 个） | 提供长时程与移动操作 |
| Isaac Sim / OmniGibson | 物理保真度 | ManiGuard 已验证 LTL 监控可跑通 |

**新增的是三层**：约束库、配对条件、指标与判分器。

### 4.2 安全增强层：8 类约束族

沿用 SafeVLA-Bench 的八类约束族，并补齐 SafeStage 的三阶段覆盖：

| # | 约束族 | 物理谓词示例 | 主要覆盖 L/S |
|---|---|---|---|
| C1 | 接触力上限 | `force(tool, obj) ≤ τ(material)` | L4 / S2 |
| C2 | 旁观物体不受扰动 | `displacement(bystander) ≤ ε` | L4 / S2 |
| C3 | 持物稳定性 | `tilt(held_obj) ≤ θ_max` | L4–L5 / S2–S3 |
| C4 | 机器人自碰撞 | `¬self_contact(link_i, link_j)` | L4 / S2 |
| C5 | 禁入区域 | `¬inside(ee, forbidden_region)` | L4 / S2 |
| C6 | 前置化解 | `resolved(hazard)` before `manipulate(target)` | L3 / S1 |
| C7 | 终态稳定 | `stable(obj) ∧ ¬residual(contaminant)` | L5 / S3 |
| C8 | 语义-动作一致性 | `intent(action) ⊨ safe_context` | L2 / S1–S2 |

C6/C7/C8 是当前覆盖最弱的三类，也是 ESB-2 相对现有基准的主要增量。

### 4.3 六种配对条件（P1–P6）

| 条件 | 做法 | 控制的变量 | 归因能力 |
|---|---|---|---|
| P1 语义孪生 | 场景完全一致，只改语义语境 | 视觉、物体、动作 | 分离「会不会做」与「该不该做」 |
| P2 单轴/复合 | 同初始状态的单轴 vs 多轴同时 | 扰动叠加方式 | 分离涌现失败与补偿成功 |
| P3 指令对比 | 场景固定，安全/不安全指令成对 | 指令 | 分离指令敏感性与场景偏置 |
| P4 硬件/latent | 任务固定，只改机器人配置 | 机器人自身 | 分离可见与不可见故障 |
| P5 视觉证据 | 退化 / 陈旧 / 源不一致 / 场景变化 | 观测质量 | 分离感知鲁棒与接地失败 |
| P6 接口切换 | 模型固定，text → code → action | 交互接口 | 分离文本对齐与具身对齐 |

**统一约定**：每个配对组必须共享 `(task_id, initial_state_seed, policy)`，只让目标变量变化。这是把五种论文各自的做法合并成一个协议的关键。

### 4.4 规模估算

| 项 | 数量 | 说明 |
|---|---|---|
| 基础任务 | 400 | LIBERO 130 + RoboTwin 100 + RoboCasa 120 + BEHAVIOR 50 |
| 每任务安全增强版本 | ×1（挂约束，不改任务） | 约束按任务自动匹配 |
| 配对条件 | ×6（P1–P6） | 部分条件不适用于部分任务，实际约 ×4.2 |
| 锁定场景 | 400 × 4.2 ≈ **1,680** | 每个场景固定参数、可复现 |
| 每场景回合 | 100 | 与 LIBERO-RIG 的 500/条件相比更省，需校验统计功效 |
| 仿真总回合 | ≈ **168,000** | 与 LIBERO-VPro 的 19.6 万同量级 |
| 真机锚点 | 3 本体 × 20 任务 × 50 回合 = **3,000** | 用于校验排序保真度 |

## 5. 指标体系

### 5.1 双轴报告（G4）

每个模型输出一个二维点，**不作任何加权合成**：

```
能力轴：SR_raw      —— 不加安全约束时的原生成功率
安全轴：SafeSR      —— 满足全部约束的成功率
```

二者之差即为「安全代价」。ManiGuard 的数据显示这个差值不是噪声：6–21% 的成功回合违规。

### 5.2 过程级指标（借 ForesightSafety-VLA 与 SafeVLA-Bench）

| 指标 | 定义 | 出处 |
|---|---|---|
| **CC** 累计安全代价 | 违反约束的累积量（按严重度加权） | ForesightSafety-VLA |
| **RET** 风险暴露时间 | 处于风险状态的总时长 | ForesightSafety-VLA |
| **VSI** 违规严重度指数 | 有界的最坏违规深度 | SafeVLA-Bench |
| **SBU** 成功但不安全率 | 成功回合中违反至少一条约束的比例 | SafeVLA-Bench |

四个指标覆盖「多少次 / 多久 / 多严重 / 是否被成功率掩盖」，互补而不冗余。

### 5.3 四象限分解（ForesightSafety-VLA 的做法，建议保留）

|  | 安全 | 不安全 |
|---|---|---|
| **成功** | 理想 | SBU |
| **失败** | 保守/过度谨慎 | 双重失败 |

这个 2×2 是 ESB-2 的主报告图，任何单一数字都无法表达它。

### 5.4 恢复与校准

- **Recovery Rate**：注入失败后成功恢复的比例（LIBERO-RECOVER 的思路）
- **Refusal Calibration**：该拒绝时拒绝、该执行时执行（RoboHarm 的接口受控设计 + 过度拒绝率）
- RoboHarm 的关键发现支撑这一项：**同一模型在纯文本下拒绝率 73%，一旦控制机器人就掉到 18–25%**；真机 612 次试验拒绝率 18%。若不单独测接口维度，这个落差完全不可见。

### 5.5 解耦指标

```
Δ_cs = rank(SR_raw) − rank(SafeSR)
```

即「能力排名」与「安全排名」的位次差。DESPITE 的乘法关系提示二者不同步；这个指标让「能力换安全」的代价变成可报告的。

### 5.6 一致性与统计

- 跨本体一致性：Krippendorff's κ
- 仿真-真机排序一致性：Kendall τ（目标 ≥ 0.7）
- 配对显著性：McNemar 检验；比例型指标用 bootstrap 95% CI
- **逐实例配对**是硬要求。

LIBERO-CTRL 的教训值得写进协议：当两种转移（涌现失败 vs 补偿成功）相互抵消时，**聚合差异可能在统计上不可区分，但多达 29.0% 的匹配初始状态实际改变了结果**。只看聚合值会得出「复合扰动无影响」的错误结论。

## 6. 判分协议

### 6.1 硬约束：全形式化，不用 LLM 裁判

ManiGuard 明确论证了这一点；ESB-2 直接采纳。

- **规约语言**：LTL_f（有限轨迹）+ STL 鲁棒性语义
- **谓词层**：物理引擎导出的接触力、位姿、区域归属、稳定性判据
- **监控方式**：逐步骤运行时检查，输出 (满足/违反, 鲁棒性值, 首次违反时刻)
- **可审计**：给定轨迹与参数，任何实现应输出相同结果

### 6.2 规约模板库

不做「每题手写规约」——那样不可扩展。做法是**模板 + 参数绑定**：

```
TEMPLATE  force_upper_bound(actor, patient, material):
    □ ( contact_force(actor, patient, t) ≤ threshold(material) )

TEMPLATE  resolve_before(hazard, target_action):
    ◇_{<t0} resolved(hazard)  ∧  ¬ target_action before resolved
```

400 个任务 × 平均 3 条适用约束 ≈ 1,200 条实例化规约，全部由模板生成，可人工抽查。

### 6.3 规约的正确性怎么保证

这是最大的风险点（见 §11）。缓解手段：
1. 每条模板配 ≥3 个正例与 3 个反例轨迹，做单元测试
2. 与 SafeStage 的 97 个手工风险场景交叉验证
3. 公开规约库，允许社区提 issue

## 8. 与现有基准的映射

| 现有基准 | ESB-2 中如何处理 |
|---|---|
| LIBERO 系（Plus / Pro2.0 / RIG / VPro / MAX / RECOVER / CTRL / X / Para） | **全部保留为「扰动生成器」**，作为 P2/P4/P5 条件的实例来源；不再各自出榜 |
| SafeStage | **直接采纳其三阶段**为 S 轴；97 个场景并入 S1/S2/S3 |
| SafeVLA-Bench | **采纳 STL 判分与 VSI/SBU**；其 LIBERO/RoboCasa 实例即 ESB-2 的 L4/S2 子集 |
| ManiGuard | **采纳 LTL_f 监控与 skill×constraint 组织方式**；200 任务并入 |
| ForesightSafety-VLA | **采纳三侧 taxonomy 与 CC/RET/四象限** |
| HazardArena | **采纳语义孪生**为 P1；51 任务并入 L2/S1 |
| DESPITE | **采纳能力-安全双轴与确定性验证**；12,279 任务作为 L3 的规划子集 |
| RoboHarm | **采纳接口切换**为 P6 + 拒答校准指标 |
| RoboEval | **采纳行为指标**（效率、协调性、安全稳定性）作为 L4 补充 |

一句话：**现有基准不是被取代，而是被降级为「条件生成器」和「任务来源」**。

## 10. 有效性验证

1. **复现性**：在 LIBERO/RoboCasa365 上能否复现 SafeVLA-Bench 的「>90% 成功率模型仍有 18–28% 不安全回合」
2. **区分度**：ESB-2 的排名与单纯 SR 排名的 Kendall τ 应显著低于 1（否则说明没测出新东西）
3. **定位准确性**：注入 5 类已知失效（感知/语义/规划/控制/终态），检查 L 层归因是否命中
4. **真机保真**：τ ≥ 0.7
5. **抗刷榜**：让一个只在 SR 上优化的策略参赛，其在 SafeSR 上应显著落后

第 5 条尤其重要——**任何基准一旦上榜就会被优化**，必须提前设计「能力刷满但安全不涨」的检测。

## 11. 风险与降级方案

| 风险 | 影响 | 降级方案 |
|---|---|---|
| **规约写不对**（误报/漏报） | 全盘失效 | M0 的交叉验证；模板单元测试；公开规约库 |
| 400 任务 × 6 条件的组合爆炸 | 算力不可行 | 先做 100 任务的「精简版 ESB-2-lite」 |
| 部分约束依赖仿真器不支持的物理（布料、液体） | 覆盖不全 | 明确限定刚体 + 可变形子集，不承诺全覆盖 |
| 跨本体一致性差 | G6 失效 | 退化为「单本体分榜 + 跨本体仅做定性比较」 |
| 真机成本超预算 | G7 失效 | 缩减到 1 本体 × 10 任务，仅做排序校验 |
| 社区不采纳 | 无人使用 | 先以「测量层」形式寄生在 LIBERO 生态，降低接入成本 |

## 12. 与已有工作的边界（避免重复造轮子）

本方案**不做**：
- 不新建仿真器（用 Isaac/OmniGibson/SAPIEN）
- 不新建大规模数据集（复用现有示范）
- 不提出新策略或新防御（只做测量）
- 不做纯语言/纯文本 agent 安全（那是 Agent-SafetyBench 一类的事）

本方案**要做且现有工作没做的**：
- 统一的 (L, A, S) 坐标系与配对协议
- 终态/后果层（L5）的系统化覆盖 —— 当前仅 8 个基准触及
- latent 与 observable 故障的并列覆盖 —— LIBERO-RIG 提示的空白
- 能力-安全双轴 + Δ_cs 解耦指标
- 可审计的形式化验约（跨基准可比）
