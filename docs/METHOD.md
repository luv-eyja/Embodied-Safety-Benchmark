# 方法与数据说明

更新日期：2026-11-03。历史关键词标签与旧 Excel 字段不再承担新的分类统计。

## 1. 范围与样本来源

调查具身智能的能力、鲁棒性和安全评测，同时保留支撑评测的数据集、平台与方法。软件代理安全作为邻接研究单列，不把软件工具执行等同机器人动作。

初始候选来自 Safety in Embodied AI 的本地快照：人工目录 594、作者复核 157、自动筛查 1,882 条，去重 2,633 条。原始 `rows.json` 保留 193 条（库内 163、库外 30）。这是历史筛选数，不代表网站当前状态；自动筛查不等于人工验证。

当前 122 条中，按既有项目入口审计选择 62 条精读分类，60 条未找到已确认入口的档案不扩读。样本偏向公开项目和机械臂/VLA，不能支持领域整体频率或唯一性结论。本轮没有重做全领域系统检索；可重复检索式、逐篇排除理由和引文追溯列为后续任务，不称本库为系统综述。

## 2. 身份与来源

条目数、论文数、任务数、轨迹数、场景数分别计量。条目沿用原名称并分配稳定 ID；合并条目暂不拆分，阅读版本与边界见笔记。

`survey_paper_registry.json` 保留原表 193 行，按确切题名、arXiv ID 与已有 DOI 别名连接 62 篇已读来源；6 篇未匹配来源补入，共 199 个书目记录。不按相似题名自动合并。原 Excel 与 `rows.json` 不覆盖。此前来源审计的“表外 7 项”是条目关系数，与“新增 6 个书目”单位不同。

旧 registry 从题名和摘要匹配使用关系，只生成候选关联。来源审计覆盖 25 项（表内 18、表外 7），明确的 `exclusive_source` 覆盖启发式角色。LIBERO、RoboCasa、CARLA、LIBERO-Para 已修正来源；STARS 归为方法。原表使用关联不是经过核验的独立采用量。

## 3. 分类与未知值

人工源数据是 `benchmark_survey_annotations.json`，依据正文笔记中的方法、评测、结果章节。每条保留分类理由。

| 轴 | 编码规则 |
|---|---|
| 主要成果 | 任务集、训练数据集、仿真平台、评测框架、方法五选一；按本次所读来源的主要贡献，不否认附带贡献。 |
| 具身关联 | 直接评测、研究底座、软件代理邻接研究三选一。离线感知／符号规划可以研究具身问题，但不因此成为闭环控制。 |
| 目标 | 能力、鲁棒性、安全可多选；出现语言、接触或失败等词不自动构成安全证据。 |
| 执行层级 | 图像／视频、离线轨迹、符号规划、仿真、真实执行、真实数据等分开。 |
| 真机证据 | 执行实验、模拟／真实配对、仅真实数据、实体测试件、未知、不适用分别标记。 |
| 档案 | `unreviewed`、空值与空列表表示本轮未分类，不解释为没有相关能力或安全属性。 |

互斥类型合计 62，多选标签不可相加。场景 × 目标矩阵仅统计同一条目上的标签共现，**未证明每种场景分别开展了该目标的实验**。逐格列成员，空格不等于领域空白。

本轮为单轮人工编码，尚未独立双人复核。多功能项目的主类型具有判断空间，应结合理由阅读，不能仅按名称含有 Bench 或 Dataset 判定。

## 4. 比较单位与协议

逐项列评测单位、指标含义及分母、对照／划分方式、重复和统计边界。问题、轨迹、rollout 与任务类别不能混合求规模中位数，安全率与成功率不能互换。

同名指标只有在分母、任务分布、重置、控制频率、种子、失败规则和评分器一致时才可能直接比较。本轮没有跨论文分数重算或综合排行榜。

文档里出现的缩写与专有名词统一进 `benchmark_glossary.json`（95 条），由 `build_benchmark_glossary.py` 渲染成 `docs/GLOSSARY.md`；每条 benchmark 文档的第 10 节只列该文实际用到的词，并给“英文全称／中文名／一句话解释”。规则：

- 解释用本库自己的话，不摘抄论文；每个指标都写清分母与配套指标（例如 USR 的分母是全部 episode，USR/SR 才是成功中的违规比）。
- 只列该文出现的词，不给每篇塞一份全表；未命中的词说明它没在这篇里出现，不必查。
- 同一个缩写在不同基准含义不同时（SR 可以是成功率、拒绝率、整体成功率或安全解决率），在该词的“常见误读”里写明，并在文档第 10 节末尾单列本文最容易读错的地方。
- 词表条目必须同时有一句话解释和详细解释，校验脚本会拒绝过短的条目，避免出现“用缩写解释缩写”。
- 产品、机构、许可证、会议与基准名不是“可解释的概念”，只标类别（例如 GPT-4o（LLM 模型）、MIT（开源许可证）、CoRL（会议／期刊））：数据在 enchmark_names.json，标了 inline 的词在正文首次出现处加括号，基准名不加，避免打断论文标题；每条文档第 10 节末列出本文出现的基准／数据集／平台名称及其类别。

## 5. 阅读、引用与成果

62 项核查方法／场景／评测／结果重点章节，笔记在 `benchmark_paper_reviews.json`；实际阅读版本、作者、正文地址和哈希在 `benchmark_reading_sources.json`。下载不等于已读，也未声称审完全部附录或复现实验。10 项历史 `fulltext.status` 与本轮 `paper_review` 独立，旧 A/B/C 仅作历史元数据。

引用快照 62 项全部有已核验观测（2026-11-04；LIBERO-Para、RoboCasa、CARLA 此前因 HTTP 429 留空，本轮补查）。来源一致的旧观测可沿用，但须显示观测日期。版本计数不相加，0 与空值不同，被引量不等于采用量。没有正式出版证据时不猜测录用状态。

除被引数外，另记录两种“谁在引用”的证据，规则如下：

| 口径 | 接口 | 判据 | 不是 |
|---|---|---|---|
| `cites` | OpenAlex `filter=cites:<work_id>` | 该论文的参考文献里含本记录 | 论文真的运行了该 benchmark |
| `arxiv` | arXiv `cat:cs.RO 或 cs.CV` + `abs:"名称"`，再逐条字面核对标题／摘要并保留命中片段 | 摘要里出现该名称 | 引用或采用 |
| `cited_by_count` | OpenAlex Work 记录字段 | 该记录的计数 | 与 `cites` 长度相等；跨库可比 |

`cited_by_count` 与 `cites` 长度来自不同更新流程，允许相差几条，不取平均也不补齐。名称是常用词或与别的项目重名的条目（当前 7 个，如 DESPITE、ORBIT、STARS、IS-Bench）只保留检索记录、不报命中数，因为字符串命中无法分辨所指。`cited_by_count` 早于来源论文的引文记录是数据库元数据错误，年份跨度统计会排除它们，逐条清单保留原样。

论文实验结果与本库综合判断分别标明。作者自用、只提及、作为训练数据和独立运行基准尚需进一步区分。

每个条目文档的第 9 节给出使用明细：谁、用什么模型、以什么方式用、报了什么数。数据源为 `benchmark_usage_records.json`，原始句子在 `benchmark_usage_evidence.json`（由 `collect_usage_evidence.py` 抽取）。规则：

- 只从论文摘要（OpenAlex 摘要或 arXiv 摘要）里取提到该基准的句子，逐篇判读；判读依据写在记录里，可回溯到原文片段。
- 一条记录的六个字段都必填：论文、年份、被测模型、用法、评测范围与指标、报告结果。摘要没写数值就写“摘要未给数值”，不用别处数字补。
- 用法分档：训练后评测／直接评测（含零样本）／预训练数据／微调（SFT 或 RL）／扩展或派生基准／审计与诊断／只批评或参照。“用到数据”和“跑出分数”不混为一谈。
- 名称歧义或同名项目（DESPITE、ORBIT、STARS、INFUSE、VIPS、SafeBench 的 LVLM 同名数据集）不产出使用记录，只写口径提示，避免把无关论文算成使用证据。
- 没有可判读片段时，明确写“本轮没查到”，不写成“没人用”。

## 6. 项目资源

重点条目的入口审计为 47 项已确认、12 项仅平台入口、3 项候选。链接核查日期单独保存，不冒充本轮重新联网检查。入口存在不等于可以运行。

代码、数据、许可证、评测器与基线完整性为 `not_audited`，运行复现为 `not_performed`。后续需记录提交版本、资产访问条件、依赖、命令、日志和成本，未取得证据不标为已复现。

每个条目文档的第 8 节另有项目源核查，数据源为 `benchmark_project_reviews.json`，回答问题：涉及领域、测试目的与构建方法、测试缺陷、与具身智能安全的相关性、被测对象与关键结论。写法约束如下：

- 项目页与 README 只作补充，事实以已读正文为准；两者冲突时以论文正文为准并在该节注明。
- 抓取方式为项目页 HTML 与仓库 README 的纯文本（每条保留约 4,200 字符，截断），未运行代码、未下载数据集，未核对提交历史。
- “被测对象与关键结论”只写论文或项目页明确给出的模型与数字；项目页缺失时写“未取得完整模型清单”，不猜测。
- 项目入口与实际项目不符时（例如同名产品）按“入口不可用”记录，不把无关内容当证据。
- 安全相关性分三档描述：直接（基准本身给风险／违规指标）、间接（测能力或失效机制，可支撑安全分析）、邻接（软件代理或平台层）。

## 7. 生成链与校验

```text
人工分类 + 正文笔记 + 来源版本 + 引用快照 + 项目入口审计
  → benchmark_survey.json / survey_paper_registry.json
  → 条目分类、索引、比较矩阵、覆盖与共同特征
  → benchmark_survey.xlsx（概览、分类、协议、论文证据）
```

日常运行 `build_benchmark_survey.py`；修改阅读笔记时先运行 `build_benchmark_paper_report.py`，其末尾应用分类层。三项旧分析脚本接入新链，不再读取父目录关键词覆盖结果。新链在本仓库内完成，旧源数据抓取脚本作为历史工具保留。

`validate_benchmark_outputs.py` 检查文档、来源／引用身份、历史全文标记与范围；`validate_survey_outputs.py` 检查分类、成员集合、指标分母、193 行保留、链接、工作簿输入哈希和导出结构。工作簿另检查公式计算、筛选、冻结窗格，并渲染核查可读性。文档一致性校验不等于外部项目实验复现。
